# AlignmentPipeline (Paired-End FASTQ / BAM / SRA)

Author: Shashwat Sahay (shashwat.sahay@charite.de)

Unified paired-end alignment, realignment, and QC pipeline for **WGS**, **WES**, and **Panel** sequencing data. Supports three input modes from a single Snakemake workflow:

1. **FASTQ metadata sheet (`metadata`)** — multi-run / multi-lane paired-end FASTQs
2. **BAM file (`bamfile`)** — extracts paired-end reads and realigns from scratch
3. **SRA accession (`sra` / `sra_id`)** — downloads and converts SRA runs to paired-end FASTQs (with optional `.ngc` key file for controlled-access data)

> **Requirement:** Sequencing data must be paired-end.

---

## Prerequisites & Installation

To run the pipeline, make sure you have a working Snakemake installation in a conda/mamba environment (recommended: `miniforge3`).

Clone the repository:

```bash
git clone https://github.com/ChapuyLab/halos-alignmentPipeline.git
cd halos-alignmentPipeline
```

Create and activate the base Snakemake environment:

```bash
mamba env create -f workflow/envs/halos-base.yaml
mamba activate halos-base
```

Per-rule conda environments are defined in `workflow/envs/` and managed automatically by Snakemake when run with `--use-conda`.

## Input Modes

Provide **exactly one** of `metadata`, `bamfile`, or `sra` (or `sra_id`) in `config/config.yaml`:

1. **FASTQ Metadata (`metadata`)**: Path to a CSV/TSV metadata sheet with the following columns (additional columns are ignored):

   | Column Name | Description | Example |
   | :--- | :--- | :--- |
   | `PATIENT_ID` | Patient ID matching `pid` in config | `RTC81D1-DNA` |
   | `SAMPLE_TYPE` | Sample name/type matching `sample` in config | `S1` |
   | `SAMPLE_NAME` | Combined ID (`{PATIENT_ID}_{SAMPLE_TYPE}`) | `RTC81D1-DNA_S1` |
   | `RUN_ID` | Sequencing run ID | `RUN01` |
   | `LANE_NO` | Sequencing lane ID | `L001` |
   | `READ` | Paired-end read designation (`R1` or `R2`) | `R1` |
   | `FASTQ_FILE` | Absolute path to the FASTQ file | `/path/to/RTC81D1-DNA_S1_R1.fastq.gz` |

   *Note: If the metadata sheet contains multiple samples/PIDs, only the `(pid, sample)` pair specified in the active config file is processed.*

2. **BAM (`bamfile`)**: Path to an aligned or unaligned BAM file. `workflow/scripts/prepare_fastq.py` fixes `MT5:` headers if present, collates pairs, and extracts paired-end FASTQs via `samtools fastq`.

3. **SRA (`sra` or `sra_id`)**: NCBI SRA run accession (e.g., `SRR12345678`). `workflow/scripts/prepare_fastq.py` downloads the run with `prefetch`, converts it to paired-end FASTQs with `fasterq-dump --split-files`, and compresses with `pigz`.
   - **Controlled-access SRA (`ngc` or `ngc_file`, optional)**: Path to a dbGaP/SRA `.ngc` key file passed via `--ngc` to `prefetch` and `fasterq-dump`.

## Pipeline Preparation

> **Recommended for Large / WGS Cohorts (Job Arrays):** We prefer submitting cohorts via **HPC job arrays** using the per-sample wrapper scripts (`1.sh`, `2.sh`, ...) generated by [`Helper.ipynb`](Helper.ipynb). Job arrays let you dynamically throttle how many samples run concurrently based on **cluster and storage availability**—which is especially important for **WGS data**, where parallel intermediate FASTQ/BAM files can substantially increase temporary storage usage. For ease of use on smaller cohorts or when automated orchestration is preferred, a cohort-level Snakemake wrapper ([`cohort_Snakefile`](cohort_Snakefile)) is also provided.

### Using `cohort_Snakefile` (Automated Multi-Sample Execution)

For automated cohort runs without manually launching per-sample scripts, use [`cohort_Snakefile`](cohort_Snakefile) with [`config/cohort_config.yaml`](config/cohort_config.yaml). It generates each sample's config YAML and subcalls `workflow/Snakefile` in parallel per sample:

```bash
snakemake -s cohort_Snakefile --configfile config/cohort_config.yaml --cores 16
```

`cohort_config.yaml` supports any execution engine (local, SLURM, SGE, LSF, PBS, etc.):
- **Local**: Leave `cluster_profile` and `executor` unset (uses `per_sample_cores`).
- **Any Snakemake profile (SLURM, SGE, LSF, PBS)**: Set `cluster_profile: /path/to/profile` and `per_sample_jobs`.
- **Snakemake executor plugins**: Set `executor` (e.g., `"slurm"`, `"sge"`, `"lsf"`).
- **Custom cluster flags**: Set `extra_snakemake_args` (e.g., `'--cluster "qsub -pe smp {threads}" -j 10'` for SGE or `'--cluster "bsub -n {threads}" -j 10'` for LSF).

### Using `Helper.ipynb` (Script Generation for Multi-Sample Cohorts)

The pipeline processes **one sample per Snakemake run**. For cohorts or batch runs, use [`Helper.ipynb`](Helper.ipynb) to generate per-sample YAML configs and wrapper `.sh` scripts:

1. Copy `Helper.ipynb` into your project workspace directory.
2. Edit **Step 2** in the notebook:
   - Set `INPUT_MODE` to `"fastq"`, `"bam"`, or `"sra"`.
   - For `"fastq"`, set `METADATA_PATH`. For `"bam"` or `"sra"`, populate `SAMPLES` with per-sample dicts (`pid`, `sample`, `library_prep_kit`, and `bamfile` or `sra` + optional `ngc`).
   - Configure reference paths (`GENOME_FASTA`, `DBSNP_VCF`, `TARGET_FILE`, `BAIT_FILE`, `CHROM_SIZES`, `DICT_GENOME`), output/scratch paths (`BASE_OUTPUT_PATH`, `SCRATCH_DIR`, `SCRIPT_PATH`), trimming options (`TRIM_ADAPTERS`, `ADDITIONAL_CUTADAPT_PARAMETER`), and execution settings (`RUN_LOCAL`, `SLURM_SMK_PROFILE`, `CONDA_ACTIVATE_PATH`).
3. Run all cells to generate `<work_dir>/view-by-pid/<pid>/<sample>/merged-alignment/<pid>_<sample>.yaml` and `<SCRIPT_PATH>/<n>.sh`.

### Manual Configuration (`config/config.yaml`)

Base your config on `config/config.yaml`:

- **Sample & Sequencing**: `SeqType` (`"WGS"`, `"WES"`, or `"Panel"`), `library_prep_kit` (defaults to `"Unknown"`), `pid`, `sample`.
- **Input**: Exactly one of `metadata`, `bamfile`, or `sra` (plus optional `ngc` for SRA).
- **Directories**: `work_dir`, `log_dir` (defaults to `{work_dir}/logs`), `scratch_dir` (optional; intermediate FASTQs/BAMs are stored here, defaulting to `work_dir`).
- **Reference & Targets**: `genome` (BWA-indexed FASTA), `dbsnp` (`.vcf.gz` for BQSR), and for `WES`/`Panel`: `target_regions`, `bait_regions` (optional; computed from `target_regions` if omitted), `chrom_sizes`, `dict_genome`.
- **Trimming & Options**: `trim_adapters` (`True`/`False`), `adapter_forward_read`, `adapter_reverse_read`, `extra_cutadapt_params`, `extra_samtools_convert_params`, `max_coverage` (defaults to `10000`).
  > **Note (`extra_cutadapt_params`):** Modern exome library preparations such as **Agilent SureSelect V8** include UMI tags at the start of the reads. If your data contains these UMI tags, set `extra_cutadapt_params: "-u 5"` (with `trim_adapters: True`) to trim them off before alignment.

## Running the Pipeline

### 1. Cluster Execution with Dynamic Conda Environments (Recommended)

```bash
cd <Path/to/work_dir>
snakemake -j 10 --configfile <Path/to/config.yaml> \
  --use-conda --conda-frontend mamba \
  --conda-prefix <Path/to/local/conda_envs> \
  --profile <Path/to/pipeline_dir/profile> \
  --snakefile <Path/to/pipeline_dir/workflow/Snakefile>
```

> **Note:** Run for a single sample first so Snakemake builds all per-rule conda environments under `--conda-prefix` before launching parallel cohort jobs.

### 2. Running with Singularity on HPC

```bash
cd <Path/to/work_dir>
snakemake -j 10 --configfile <Path/to/config.yaml> \
  --use-singularity --singularity-prefix <Path/to/local/Singularity> \
  --singularity-args "-B /Path/to/data_folder1/:/Path/to/data_folder1,/Path/to/data_folder2/:/Path/to/data_folder2" \
  --use-conda --conda-frontend mamba \
  --conda-prefix <Path/to/local/conda_envs> \
  --profile <Path/to/pipeline_dir/profile> \
  --snakefile <Path/to/pipeline_dir/workflow/Snakefile>
```

- `--singularity-args` must bind all external directories referenced in `config.yaml` and `metadata` (Snakemake binds the current working directory automatically).

### 3. Local / Non-SLURM Execution

```bash
cd <Path/to/work_dir>
snakemake --cores 8 --configfile <Path/to/config.yaml> \
  --workflow-profile <Path/to/pipeline_dir/profile> \
  --use-conda --conda-frontend mamba \
  --snakefile <Path/to/pipeline_dir/workflow/Snakefile>
```

## Outputs

- **Final Alignment (`{work_dir}/alignments/`)**:
  - `{pid}_{sample}_dedup.recall.cram` and `.crai`
- **QC Metrics (`{work_dir}/metrics/`)**:
  - `{pid}_{sample}.mosdepth.global.dist.txt`, `{pid}_{sample}.mosdepth.summary.txt`
  - `{pid}_{sample}_dedup.recall.flagstat`
  - `{pid}_{sample}_insert_size_metrics.txt`, `{pid}_{sample}_insert_size.pdf`
  - `{pid}_{sample}_recal_data.table`, `{pid}_{sample}_covariates.pdf`
  - `{pid}_{sample}.hs_metrics.txt` (`WES` / `Panel`) or `{pid}_{sample}_coverage.png` (`WGS`)
  - FastQC reports in `{work_dir}/fastq/{run_id}/cutadapt/` when `trim_adapters: True`
